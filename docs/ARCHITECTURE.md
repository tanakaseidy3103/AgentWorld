# Architecture

AgentWorld follows one rule: **the model proposes, Unity disposes.** Meta Llama 3.2 returns JSON that names
skills and place ids. Unity validates that JSON against the skill registry, the agent's permissions, and the
live world, then executes it on the main thread.

## Layout

```
Assets/AgentWorld/
  Scripts/Runtime      AgentWorld.Runtime (game and AI)
  Scripts/Runtime/AI   LLM client, skills, agents, missions, routing, evaluation
  Scripts/Editor       WorldBuilder: generates art, prefabs, and the scene; Windows build menu
  Tests/EditMode       pure logic: validation, skills, config, save format, evaluation
  Tests/PlayMode       the real scene with a mock LLM, plus opt-in live-Llama tests
  Art/ Prefabs/ Scenes/   generated by WorldBuilder (not in git; created on first editor load)
Assets/StreamingAssets/agents.json   agent titles, personalities, and skills
```

## Main components

| Component | File | Responsibility |
|---|---|---|
| `ILlmClient`, `OllamaClient`, `LlmConfig` | `AI/LlmClient.cs` | Provider interface; local Ollama over async `UnityWebRequest`; settings from environment variables |
| `SkillRegistry`, `Skill`, `SkillContext` | `AI/SkillRegistry.cs` | Every action as a registered skill: id, roles, parameters, `Validate`, `Execute`, safety notes |
| `AgentConfigs` | `AI/AgentConfigs.cs` | Loads and validates `agents.json`; answers "does this agent have this skill?" |
| `PlanValidator`, `AgentPlan` | `AI/AgentPlan.cs` | Parses model JSON and checks each action: registered? permitted? valid in the world? |
| `LlamaAgentBrain`, `AgentHub` | `AI/LlamaAgentBrain.cs` | Per-agent state machine (Idle, Thinking, Planning, Moving, Acting, Completed, Failed, Cancelled), memory, prompts, timeouts, cancellation |
| `MissionControl` | `AI/MissionControl.cs` | Multi-agent missions: delegation, scouting, dialogue, site selection, construction, recovery, outcome |
| `ExpertRouter` | `AI/ExpertRouter.cs` | Routes free-form requests to a specialist (Llama picks an intent; status and capability answers come from live state) |
| `Evaluation` | `AI/Evaluation.cs` | Scenarios, measured metrics, text and JSON reports |
| `StructureBuilder`, `Landmark`, `BuiltStructure` | `AI/` | Free-site search, reachable stand points, animated construction, persistence; named places |
| `NpcAgent`, `AgentIndicator`, `InspectionMarkers` | `Runtime/` | Characters, name plates, activity icons, survey flags |
| `MissionPanel`, `TerminalUI`, `TerminalBackend` | `Runtime/` | Mission Control, terminal, mission bar, commands |
| `WorldSaveManager`, `WorldState` | `Runtime/` | Versioned JSON save (v3; v1 and v2 still load) |

## Mission pipeline

```
request ─► ExpertRouter (Llama: intent) ─► MissionControl
  1. Ada: Llama → {feasible, explore[], houses, farms, message}      validated: real place ids, limits, skills
  2. Grace: move_to + inspect; Unity measures free sites → SiteReport in shared memory
  3. Dialogue: Grace and Linus each say one line (Llama), grounded in the measured numbers
  4. Ada: Llama → {build_at[], farm_at, reason}                          validated: explored? within capacity?
  5. Linus: build_house / build_farm; if a site filled up, Unity switches to another reported site
  6. Outcome: Succeeded | Partial | Failed | Cancelled | Unsupported (+ evaluation report if run via eval)
```

Every model call has a timeout (default 120 s) measured on Unity's main thread, and can be cancelled. Rejected
JSON gets one retry with the validator's error. Dialogue failures are logged and skipped, never replaced with
invented text.

## Threading

All `async` continuations resume on Unity's main thread (`UnityWebRequest` plus `Awaitable`), so skills can
use Unity APIs directly. Timeouts are checked per frame on the main thread rather than with background timers.

## Extension points

- **New skill:** register it in C# (`SkillRegistry.Register`) and add its id to an agent in `agents.json`. See the developer guide.
- **New LLM provider:** implement `ILlmClient` and assign `AgentHub.Llm`. Only the local Ollama provider exists today.
- **New evaluation scenario:** add an entry to `Evaluation.Scenarios`.

## Unity notes

- Each `MonoBehaviour` lives in a file with the same name as its class (required for scene serialization).
- `NpcAgent.Brain` is created on demand so that a domain reload during Play mode doesn't leave it null.
